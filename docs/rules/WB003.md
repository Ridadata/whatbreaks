# WB003 — column added

A model produces a column it did not before. Always `safe`.

Additive schema changes cannot break a consumer that selects by name, which is
everything dbt generates.

It is reported rather than suppressed because "what changed in this model's
contract?" is a question reviewers ask, and the answer is more useful than
silence. Under the default `--fail-on=breaking` it does not fail CI, and the
markdown reporter folds it away so it cannot crowd out a real break.

## The case where an addition is not safe

Adding a column to a model that a downstream model reads with `SELECT *` widens
that downstream model too, which can collide with a column it already has. That
is `WB010` and is not implemented yet — see [limitations](../limitations.md).

## Example

```
    safe  WB003  column dim_customers.lifetime_value was added
          confidence: likely
```
